# The Positional Program (opened 2026-07-26)

The counting phase closed with the profile verdict: the four
verified books (sqrt-growth, two-scale funding, spike census,
oscillation) admit nearly every density profile.  What no lab
world can do — 347/347 failures to defend — is *positional*:
arranging spikes, basis mass, and poor streams so that total
service breakdown survives every deletion.  This document opens
the phase that proves no arrangement works.

## The single question (the reduction)

`endgame_service_breakdown`: every counterexample must run, for
every infinite deletion B, cofinally many targets n at which
EVERY wealthy w ≤ n has n − w ∉ A ∖ B.  Equivalently
(`served_targets_never_fail`), one wealthy server anywhere saves
a target.  The positional program's goal: prove some deletion
always finds served targets cofinally — no arrangement of
wealth and basis can keep all reflections dead forever.

## First formal targets

1. **Reflection interaction.** At a breakdown target n, the
   spike set S(n) and n − (A∖B) are disjoint.  For two
   breakdown targets n < n′ of the same deletion: S(n) sits
   inside S(n′)-modulo-cap-drift, and both reflections must
   die.  Formalize the two-target interaction: what does
   (n′ − n) + S(n) vs S(n′) force?  (Difference-shift of dead
   reflections — connects to the repair mine's forced repeated
   differences.)

2. **The wealthy stream's own addresses.** Wealth is 2-adically
   pinned; breakdown demands n − w dead for all wealthy w.
   Combine: breakdown targets' residues are constrained by the
   wealth tower's addresses (n ≡ dead-class + w-class).  Mine
   the residue arithmetic of breakdown targets against
   `drain_wealth_addresses` — the positional analogue of the
   old collision program, now with the reduction behind it.

3. **Deletion design.** The deleter moves last.  Design B to
   maximize served targets: B avoiding all wealthy reflections
   (B ∩ (n − S) = ∅ arranged per-scale) — the dodge
   generalized from matchings to server sets.
